# ML Service

**Location:** `services/ml-service/`
**Port:** 8000
**Framework:** FastAPI + Python 3.12

## Quick Start

```bash
cd services/ml-service
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8000
```

Swagger UI available at `http://localhost:8000/docs`.


## API Endpoints

All endpoints accept and return JSON. No authentication required — the ML service is internal only (called by the Express backend, never directly by the browser).

### GET /health

Returns `{ "status": "ok", "service": "fotnep-ml", "version": "1.0.0" }`. Used by the backend health check.

### POST /predict-match — Algorithm 1

Reputation-weighted aggregation of votes into win/draw/loss probabilities.

Input:
```json
{
  "matchId": "string",
  "votes": [
    { "userId": "string", "outcome": "home_win|draw|away_win", "reputation": 85.0 }
  ]
}
```

Output:
```json
{
  "matchId": "string",
  "prediction": { "homeWinProb": 0.5833, "drawProb": 0.2222, "awayWinProb": 0.1944 },
  "confidence": 77.8,
  "voteBreakdown": { "homeWin": 3, "draw": 1, "awayWin": 1 }
}
```

Returns `{ "error": "NO_VOTES" }` (200) when the votes array is empty.

### POST /compare-players — Algorithm 2

Cosine similarity between two players' six-attribute vectors.

Input:
```json
{ "playerAId": "mongo_object_id_string", "playerBId": "mongo_object_id_string" }
```

Output:
```json
{
  "playerA": { "id": "...", "name": "...", "stats": { "pace": 72, ... } },
  "playerB": { "id": "...", "name": "...", "stats": { "pace": 65, ... } },
  "similarityScore": 99.1,
  "attributeComparison": { "pace": { "playerA": 72.0, "playerB": 65.0 }, ... },
  "strengths": { "playerA": ["pace", "dribbling"], "playerB": ["defending", "physical"] }
}
```

Returns `{ "error": "PLAYER_NOT_FOUND" }` (200) when either ID is invalid.

### POST /optimize-squad — Algorithm 3

Greedy ELO-ranked starting XI selection given a pool of player IDs and a formation.

Input:
```json
{
  "teamId": "string",
  "availablePlayerIds": ["id1", "id2"],
  "formationPreference": "4-3-3",
  "constraints": { "injured": [], "suspended": [] }
}
```

Output:
```json
{
  "teamId": "string",
  "startingXI": [{ "playerId": "...", "playerName": "...", "position": "GK", "bench": false }],
  "bench": [{ "playerId": "...", "playerName": "...", "position": "MF", "bench": true }],
  "formation": "4-3-3",
  "confidence": 67.4,
  "tacticalInsights": ["Lineup selected by ELO rating strength."],
  "keyMissingPlayers": []
}
```

### POST /impute-attributes — Algorithm 4

On-demand imputation of height, weight, preferredFoot, and marketValue for a single player. Primary use is inside `seed_db.py`; this endpoint enables single-player on-demand prediction without a re-seed.

Input:
```json
{
  "name": "Tej Tamang",
  "nationality": "Nepali",
  "position": "MF",
  "age": 27,
  "eloRating": 1612,
  "appearances": 27,
  "goals": 1,
  "assists": 2,
  "stats": { "pace": 65, "shooting": 58, "passing": 72, "dribbling": 67, "defending": 58, "physical": 62 }
}
```

Output:
```json
{ "height": 171, "weight": 66, "preferredFoot": "Right", "marketValue": 193000 }
```

## CORS

The ML service allows requests only from `http://localhost:3000` and `http://localhost:3001`. In production, update `allow_origins` in `main.py` to match the deployed backend domain. The browser never calls this service directly.

## Configuration

`.env` (not committed):
```
MONGO_URI=mongodb://localhost:27017/fotnep1
```

`get_db()` in `config/database.py` derives the database name from the URI path component.

## Seeding

Run order for a clean seed:

```bash
# 1. Train CatBoost (only required when CSV files change)
python scripts/train_imputer.py

# 2. Full seed — drops players collection, re-seeds all collections
python scripts/seed_db.py

# 3. Optional: top-up any team with fewer than 15 players (additive, no drops)
python scripts/seed_missing_players.py

# 4. Fix any marketValue=0 records (safe to re-run without re-seeding)
python scripts/backfill_market_values.py
```

After a full seed: 980 players (280 nepali, 100 international, 600 european), 19 teams, 24 matches, 2 demo users.

`seed_generated_players()` sets `source: 'nepali'` for Nepal-country teams and `source: country.lower()` (e.g. `'india'`, `'bhutan'`) for international opponent teams. The Player model's TypeScript enum `['nepali', 'european']` does not cover these values — the seed bypasses Mongoose via direct pymongo insert, so the data stores correctly. The TypeScript enum should be widened to `string` before production to avoid hidden validation issues.

## Integration with Backend

The Express backend calls this service via `backend/src/services/mlIntegration.ts`:

```typescript
const ML_URL = process.env.ML_SERVICE_URL || 'http://localhost:8000';

// callML<T>(endpoint, payload) — thin fetch wrapper
// Throws on non-2xx; error message taken from response.detail or statusText
export function predictMatch(matchId, votes)   // → POST /predict-match
export function comparePlayers(aId, bId)        // → POST /compare-players
export function optimizeSquad(teamId, ids, formation, constraints)  // → POST /optimize-squad
```

The frontend never calls this service directly. All three algorithms route through the Express backend.

```bash
python -m uvicorn main:app --port 8000 --workers 4
```
