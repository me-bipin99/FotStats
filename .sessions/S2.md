## 🚀 How Routes Work

### Route 1: POST /api/v1/estimate-stats (Algorithm #1: KNN)
```
Input: { name, position, goals, assists, minutes, caps, yellowCards, redCards }
Process:
  1. Get trained KNN comparator from singleton
  2. Find 5 most similar European players
  3. Estimate missing stats (Sh, SoT, G/Sh, etc.)
  4. Calculate xG = G/Sh * Sh, xA = Ast
Output: { xG, xA, similar_players, estimated_stats }
```

### Route 2: POST /api/v1/predict-match (Algorithms #3, #4: Naive Bayes + ELO)
```
Input: { homeTeam, awayTeam, formation, isNeutralVenue }
Process:
  1. Extract ELO ratings for all players
  2. Call LineupPredictor.predict_lineup() with ELO weights
  3. Call MatchPredictor.predict() for outcome probabilities
Output: { lineup, prediction: { homeWin, draw, awayWin, confidence }, narrative }
```

### Route 3: POST /api/v1/cluster-players (Algorithm #2: K-Means)
```
Input: { players: [{ playerId, name, goals, assists, minutes, yellowCards, redCards }, ...] }
Process:
  1. Build feature vectors (goals, assists, minutes, cards, defensive proxy)
  2. Get trained K-Means clusterer from singleton
  3. Predict cluster for each player (0-5)
  4. Group by cluster and identify synergy pairs
Output: { clusters: { 0: ["player1", ...], ... }, synergy_pairs, cluster_labels }
```

### Route 4: POST /api/v1/optimize-squad (Algorithm #5: Genetic Algorithm)
```
Input: { players: [{ playerId, name, position, eloRating, ... }, ...], formation }
Process:
  1. Initialize population of 100 random 11-player squads
  2. Run 50 generations:
     a. Calculate fitness for each individual (ELO + cluster bonus)
     b. Select top 50% by fitness
     c. Crossover + mutate to create next generation
  3. Return best-fitness squad (bestXI)
Output: { bestXI, formation, fitness_score, composition }
```

### Route 5: POST /api/v1/generate-insights (Rule-based)
```
Input: { player: { name, goals, assists, minutes, eloRating, caps, cards } }
Process:
  1. Get InsightsEngine singleton
  2. Apply 6 rules: form_trend, overplayed, injury_risk, scoring_streak, poor_form, consistency
Output: { insights: [{ type, severity, message }, ...], count }

Alternative: POST /api/v1/match-narrative
Input: { prediction: { homeWin, draw, awayWin }, homeTeam, awayTeam }
Output: { narrative: { outlook, factors, summary } }
```

## 🧬 Genetic Algorithm Implementation

**File:** `models/genetic_optimizer.py`

**Key Methods Implemented:**

1. **`optimize(players)`** — Main entry point
   - Calls `_initialize_population()` → 100 random 11-player squads
   - Calls `_run_evolution()` → 50 generations
   - Returns best-fitness individual

2. **`_initialize_population(players, pop_size)`**
   - Creates `pop_size` random 11-player subsets using `random.sample()`
   - Returns list of squads (each squad is a list of player dicts)

3. **`_run_evolution(population, available_players)`**
   - Runs `self.generations` iterations (default 50)
   - Per iteration:
     - Evaluates `_calculate_fitness()` for all individuals
     - Selects top 50% by fitness
     - Applies `_crossover()` (split at midpoint, swap halves)
     - Applies `_mutate()` (random player swap with `mutation_rate` probability)
   - Tracks best solution across all generations
   - Logs progress every 10 generations
   - Returns best-ever individual

**Fitness Function:**
```
fitness = (0.4 × attack_avg_rating) 
        + (0.3 × midfield_avg_rating) 
        + (0.3 × defense_avg_rating) 
        + (0.2 × balance_score)
```
- Positional balance: reward correct formation counts (1 GK, 4 DEF, 3 MID, 3 FWD)
- Rating field: scaled from ELO (rating = eloRating / 250)

## 🔍 Key Implementation Details

### KNN Route (`routes/estimate.py`)
- Input validation: Pydantic `PlayerRequest` model
- Feature engineering: Build player dict from request fields
- Model call: `comparator.find_similar_players(player_dict)` returns `(similar_players, estimated_stats)`
- Output calculation: `xG = estimated_stats["G/Sh"] * estimated_stats["Sh"]`
- Error handling: Try/catch with HTTPException 500

### Naive Bayes + ELO Route (`routes/predict.py`)
- Accepts `TeamStats` with player list (including eloRating)
- Extracts ELO dict: `{ playerId: eloRating, ... }`
- Calls `LineupPredictor.predict_lineup()` with ELO weights
- Calls `MatchPredictor.predict()` for outcome probabilities
- Handles missing ELO gracefully (default 1500)
- Returns formation + best 11 + prediction object

### K-Means Route (`routes/cluster.py`)
- Input: List of player stats (goals, assists, minutes, cards)
- Feature vector: `[goals, assists, minutes, cards, defensive_proxy, ...]` (7 features)
- Output: Cluster groups + synergy pairs + role labels (e.g., "Elite Forward", "Midfielder")
- Role label mapping: 6 clusters → human-readable roles

### GA Route (`routes/optimize.py`)
- Input: Full player list + formation string
- Converts Pydantic models to dicts
- Uses ELO as proxy for player rating (scaled to 0-10)
- Returns: Top 11 players + fitness score + position composition

### Insights Route (`routes/insights.py`)
- Two endpoints:
  1. `/generate-insights` — Player-level rules (form, workload, injury risk)
  2. `/match-narrative` — Match-level narrative (outlook, factors, summary)
- Both use `InsightsEngine` from `services/insights_engine.py`
- Fully implemented rule engine (no TODOs)
